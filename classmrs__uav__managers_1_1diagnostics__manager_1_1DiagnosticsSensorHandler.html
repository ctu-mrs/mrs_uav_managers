 Maps a config type: string to its mrs_msgs::msg::SensorStatus::TYPE_* constant, via sensor_type_t (enums/sensor_type.hpp) – X_ENUM_SEQ there is the single source of truth for the set of valid strings, so a genuinely new sensor type that's missing its mrs_msgs::msg::SensorStatus::TYPE_* constant fails to compile rather than silently degrading at runtime. Returns std::nullopt for an unmapped string (a typo in config, since the compile-time gap above is already ruled out) – the caller treats this as fatal, since silently degrading to TYPE_UNKNOWN would hide the mistake instead of making the operator fix it.
